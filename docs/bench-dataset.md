# 實測基準資料集 — 量測協定

> [← 文件索引](introduce/README.md) ｜ 對應 [`objectives.md`](objectives.md) §7-1、O-4、F-2
>
> **這份文件的存在理由**：`objectives.md` 訂了「模擬值與實驗室實測差 < 5 %」（O-4 光學、F-2 射頻）。
> 這條目標**現在無法驗收**，因為沒有一組釘選的實測值可以比對。本檔定義要量什麼、怎麼量、
> 量完的數字放哪裡，以及一筆資料如何從「待測」變成「CI 擋關」。
>
> 內層目標（對解析解 < 0.1 %，O-3/F-1）不需要這份資料，它已由純數值單元測試覆蓋。

---

## 1. 一筆有效的基準案例需要什麼

**數值本身是最不重要的部分。** 一個沒有記錄條件的量測值，半年後沒有人能判斷它為什麼對不上模型，
於是唯一的處置就是放寬門檻 —— 那等於廢掉這條目標。所以每筆案例都必須帶：

| 欄位 | 為什麼非要不可 |
|---|---|
| `value` + `unit` | 量到的數字 |
| `uncertainty` | 儀器精度 + 重複量測散布。**若量測不確定度已經接近 5 %，這條案例就不能用來驗收 5 % 的目標** |
| `date` | 實驗室狀態會漂移。過期的基準要重測，不是放寬門檻 |
| `instrument` | 型號 + 校正日期。功率計的波長設定錯了就是系統性偏差 |
| `operator` | 對不上時要找得到人問 |
| `conditions` | 見 §3 每案例列出的必記條件。**這是最常被漏掉、也最常導致無法追查的一項** |

`conditions` 的原則：**凡是模型會讀的參數，實驗時的對應物理量都要記下來。**
下面每個案例都直接列出它牽動哪些 `defaultParams`。

## 2. 案例清單

依「能鎖住多少物理」排序。前四項建議優先。

### 光學（O-4）

#### O-4.1 光纖耦合效率 ★優先
- **量什麼**：雷射 → 非球面透鏡 → 光纖，量 η = P_out / P_in。
- **怎麼量**：功率計先量透鏡前的自由空間功率（P_in），再量光纖尾端輸出（P_out）。同一顆功率計、同一波長設定。
- **必記條件**：波長 (nm)、光纖型號與長度、連接器型式（PC/APC）、耦合透鏡 catalog_id、入射光束 1/e² 直徑與發散角、對準後的最佳值 vs 典型值。
- **牽動模型**：`fiber` op 的 `coreMfdUm`(預設 5.3)、`numericalAperture`(0.13)、`coreRefractiveIndex`(1.46)、`attenuationDbPerKm`(4.0)、`lengthM`；以及透鏡的 thick-lens 幾何。
- **為什麼優先**：耦合效率同時考驗光束傳播、透鏡 ABCD、模態重疊積分三層，是最能一次驗到底的量。

#### O-4.2 AOM 一階繞射效率 ★優先
- **量什麼**：在 Bragg 角對準下，+1 階功率 / 入射功率。
- **怎麼量**：擋掉其他階，量 +1 階；再量無 RF 時的直穿功率當分母。
- **必記條件**：RF 頻率 (MHz)、**RF 驅動功率 (dBm，量在 AOM 接頭處而非訊號源輸出)**、波長、入射光束直徑、入射角（相對正向）。
- **牽動模型**：`aom` op 的 `crystalLengthMm`(22.4)、`refractiveIndex`(2.26)、`acousticVelocityMps`(4200)、`baseEfficiency`、`rfPowerMaxW`。
- **注意**：`crystalLengthMm` 已由 alembic 0120 定為 22.4 mm，這條案例會直接檢驗那個值。

#### O-4.3 AOM 階間功率比 vs 失諧
- **量什麼**：固定光路，掃 RF 頻率，記錄 +1 / 0 階功率比隨失諧的變化（至少 5 個頻率點）。
- **必記條件**：同 O-4.2，外加每點的頻率與對應功率。
- **牽動模型**：order-aware Bragg matching（見 [`aom-model.md`](aom-model.md)）。這是唯一能驗到「帶號逐階匹配」是否正確的量測。

#### O-4.4 隔離器正反向消光比 ★優先
- **量什麼**：正向插入損耗 (dB) 與反向隔離度 (dB)。
- **怎麼量**：正向量 P_out/P_in；反向把光從輸出端打進去量穿透。
- **必記條件**：波長、**入射偏振方向相對隔離器透光軸**（見 §4 陷阱）、環境溫度（Faraday 旋轉角隨溫度漂）。
- **牽動模型**：`pbs` op 的 `extinctionRatioPpDb` / `extinctionRatioSpDb`、`faraday_rotator` 的 `rotationDeg`(45)。

#### O-4.5 Glan 稜鏡消光比
- 同 O-4.4 的量法，但只針對單顆 Glan 的透光 / 拒斥軸。
- **必記條件**：入射偏振角（掃過至少透光軸 ±90°）。

#### O-4.6 TA 增益飽和曲線
- **量什麼**：固定驅動電流，掃 seed 功率，記錄輸出功率（至少 6 點，涵蓋線性區到飽和區）。
- **必記條件**：驅動電流 (A)、seed 波長、seed 光束與 TA 模態的對準狀態、外殼溫度。
- **牽動模型**：`smallSignalGainDb`(30)、`saturationPowerMw`、`outputPowerMaxMw`。

#### O-4.7 透鏡焦平面光腰
- **量什麼**：已知焦距透鏡（如 A230TM-B）後焦面的 1/e² 光腰 (µm)。
- **怎麼量**：beam profiler 或刀口法沿 z 掃描，取最小值。
- **必記條件**：入射光束直徑與發散、波長、量測面相對透鏡後頂點的距離。
- **牽動模型**：thick-lens ABCD（`radiusFrontMm`/`radiusBackMm`/`refractiveIndex`/`centerThicknessMm`）+ POP 繞射。

### 射頻（F-2）

#### F-2.1 AD9959 通道輸出電壓
- **量什麼**：各通道輸出 Vpp（50 Ω 負載），掃 `amplitudeScale` 至少 4 點。
- **必記條件**：頻率、amplitudeScale 設定值、負載阻抗、示波器頻寬與探棒衰減比。
- **牽動模型**：`fullScaleVpp`(1.0)。

#### F-2.2 放大器增益與壓縮
- **量什麼**：ZHL-1-2W+ 輸出 vs 輸入功率，掃到 1 dB 壓縮點。
- **必記條件**：頻率、輸入功率 (dBm)、供電電壓、外殼溫度。
- **牽動模型**：`rf_amplifier` 的增益/飽和參數。

#### F-2.3 同軸線插入損耗
- **量什麼**：RG316 在工作頻率（如 80 MHz）下的損耗 vs 長度，至少 2 種長度。
- **必記條件**：頻率、長度、接頭型式、量測方式（VNA 或 功率計差值）。
- **牽動模型**：cable 損耗模型（見 [`introduce/cable.md`](introduce/cable.md)）。

#### F-2.4 開關隔離度與插入損耗
- **量什麼**：ZYSWA-2-50DR 的 RF1/RF2 插入損耗與通道間隔離度。
- **必記條件**：頻率、TTL 控制狀態、供電。

#### F-2.5 RF 驅動功率 → 繞射效率 ★優先
- **量什麼**：掃 AOM 的 RF 驅動功率，記錄一階繞射效率（至少 5 點，涵蓋到飽和）。
- **必記條件**：同 O-4.2。
- **為什麼優先**：這是**唯一跨越 F-2 與 O-4 的案例** —— 它同時驗證 RF 鏈的功率計算與光學繞射模型的接合處，也是實務上最常被問「為什麼模擬跟實際對不上」的地方。

## 3. 資料放哪裡

`backend/tests/fixtures/bench/<case-id>.json`，格式見同目錄的 [`README.md`](../backend/tests/fixtures/bench/README.md)
與 `_template.json`。

一筆案例的生命週期：

```
measured: null          →  待測。CI 會列出來，不擋關
        ↓  （量測、填入數值與條件）
measured: { ... }       →  就緒。CI 要求對應的比較器存在，否則 fail
        ↓  （實作比較器）
CI 比對模擬 vs 實測      →  超過 tolerance_pct 即 fail
```

**比較器目前一個都還沒實作 —— 這是刻意的。** 第一筆真實資料的形狀（要比對整條光路的哪一個量、
從 solver 輸出的哪個欄位取）在資料到手之前是猜的，先寫等於寫錯。
`test_bench_cases.py` 會在有人塞入 `measured` 卻沒有對應比較器時大聲失敗，把「該補比較器了」變成擋關條件。

## 4. 已知陷阱（會讓你白做一輪的那種）

- **偏振方向沒記 → 隔離器/Glan 的資料作廢。** 記憶中反覆出現的誤判：「glan2 不該透光卻透光」
  幾乎都是入射偏振落在拒斥軸上，不是框架 bug（見 [`float64-audit.md`](float64-audit.md) 相關條目與
  `isolator_glan_input_pol_gotcha` 記憶）。量之前先確定入射偏振相對透光軸的角度並記下來。
- **RF 功率要量在元件接頭處**，不是訊號源面板讀值。線損與失配會吃掉數 dB，而模型算的是元件實際收到的功率。
- **AOM 沒做 Bragg align 就量會得到 ~2 % 的假結果。** 舊的直穿對準方式已作廢，量之前先按一次兩階段 Bragg align。
- **功率計的波長設定** 忘記改會造成 5–15 % 的系統性偏差 —— 剛好落在要驗收的量級上。
- **不確定度大於門檻的案例不要收進來。** 與其收一筆 ±8 % 的資料去驗 5 % 的目標，不如標記為待測。
