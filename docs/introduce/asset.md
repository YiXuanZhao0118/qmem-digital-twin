# Asset3D — 幾何 + 物理真值層

> 屬 [核心資料模型](data-model.md) 第 1 層。相關：[anchors.md](anchors.md)（anchor 標註）、[kinds.md](kinds.md)（每 kind 物理參數）、[rendering.md](rendering.md)（如何渲染）。

**Asset3D** — 可重用 3D 模型 + 其物理預設。DB 表 `assets_3d`，存：`file_path`（.glb/.stl，API `filePath`；舊文件曾叫 geometryRef）、`kind_id`（**NOT NULL，migration 0111**；預設 `unclassified`，無「無 kind」狀態）、`anchors[]`（光學介面：每個 anchor 帶方向 + aperture）、`default_params`（該零件內在物理，如某顆 Thorlabs 透鏡的焦距）、`wavelength_range_nm`、`properties.viewerHints`。**物理預設只存在這裡。**

## 相關概念

- **anchors[]** — 取代舊的 `faces[]` / `transitions[]`：每個 anchor 本身就是一個光學介面，直接帶**方向**（tri-axis）與 **aperture**。結構與 tracer 用法見 [anchors.md](anchors.md)。
- **defaultParams** — 每 kind 的代表性物理預設值（laser 780.241nm/50mW、AOM v=4200 m/s 等）見 [kinds.md](kinds.md)。
- **defaultParams 編輯：嚴格依 KIND schema（跟 object 一樣）** — Asset3DEditor 的 defaultParams **不再是自由 JSON**：當 kind 有可編輯純量 schema（lens/mirror/polarizer/laser_source…）時，渲染**結構化欄位**（`DefaultParamsKindFields`，`Asset3DEditor.tsx`），使用者只能設定 **kind 定義好的參數**——打錯 key（如 `focalMm`/`transmission`）不可能再發生。**遞迴渲染**（`ParamTree`）：純量一格 input，巢狀 object/array 往下展開到每個 leaf（number/string/bool）、依 dotted path 標示（`spatialModeX.waistUm`、`spectrum.components.0.fwhmMhz`），所以 laser_source 這種以巢狀為主的 kind 也完整顯示全部參數（不再只露 5 個 scalar）；不做 array 增刪，只編現有 leaf。葉值編輯走 `setLeafInParams`（strict clone 只留 kind key、缺的 required 由 kind default 補齊）。存檔時 `toAssetUpdate` 用 `strictDefaultParamsForKind` **丟棄所有非 kind 宣告的 top-level key**（巢狀結構保留；schema 為空的 kind 保留自由 textarea，避免誤刪）。（舊的「Kind definitions」參考面板 `KindGuidePanel`／`KIND_GUIDES`——含已退役的 faces/transitions 文字——已移除。）
  - **required vs optional 參數**：kind 的 `physics.defaultParams` 是 required（一定寫入、由 kind default 種子）；`physics.optionalParams`（`_plugin.ts` 新增、**frontend-only 不進 manifest**）是 opt-in：結構化表單渲染**空白欄位**，留空＝省略、填了＝寫入，其「缺席」本身有意義。lens 經典案例：required＝`focalLengthMm`+`transmittance`（op 實讀，`backend/app/optical/anchor_ops/lens.py:167,109`）；optional thick-lens 幾何＝`radiusFrontMm`/`refractiveIndex`/`centerThicknessMm`（+`radiusBackMm`）——**`radiusFrontMm`+`refractiveIndex`+`centerThicknessMm` 三個都留空走 thin-lens 近似（焦點在 nominal f）；都填切到精確 thick-lens ABCD（焦點在 back-vertex+BFL，op `_is_thick`）**。`radiusBackMm` 留空＝平背（真 plano-convex）；填數值＝曲背，用於以 thick-lens 等效擬合表示的非球面（如 A230TM-B：`radiusFrontMm=2.3244`/`radiusBackMm=10.308`/`refractiveIndex=1.59`/`centerThicknessMm=2.75` → EFL 4.51mm，見 [optics.md](optics.md)）。optionalParams 不種子進 asset、不污染 object 係數 baseline，所以 plano-convex 預設仍是通用 thin-lens，逐顆填 R/n/d 才升級精度（BeamScope 的 q/焦點即反映此差異）。
- **wavelengthRangeNm（不變式：asset 只住 `wavelength_range_nm` 欄、不放 asset.defaultParams）** — 由 Asset3DEditor 的 lambda min/max 欄編輯；存檔時欄位才是權威（`toAssetUpdate` 從 lambda 欄組出，v3_catalog 寫 `row.wavelength_range_nm`），v3 anchor tracer 也只讀此欄、不讀 defaultParams。**KIND 模板**仍宣告 `wavelengthRangeNm`（optical-kinds spec 不變式要求每個非 emitter optical kind 有它，且 legacy PhysicsElement seed 讀它，`components.py:667`），但 asset 端一律排除：`kindScalarParamKeys`/`kindAllParamKeys` 都剔除它 → 結構化欄位不顯示、strict 存檔丟棄；kind seeding（`Asset3DEditor.tsx:~2397`）把該值灌進 lambda 欄而非 defaultParams JSON；`draftFromAsset`（`Asset3DEditor.tsx:~280`）開檔時把 legacy 殘留在 defaultParams 的 `wavelengthRangeNm` 上抬到 lambda 欄並從 JSON 剝除。
- **viewerHints** — 驅動幾何過濾（`includeOnlyCentroids`、`deletedCentroids`、`recenterOrigin`），渲染端如何消費見 [rendering.md](rendering.md)。
