# The optical physics model

> The kind list is in [kinds.md](kinds.md); coordinates / anchor normals in [anchors.md](anchors.md); the AOM alignment geometry additionally in [aom-model.md](../aom-model.md) + `../aom_align_*.png`.

## Polarization

Tracked with **Jones calculus** (`optical/jones.ts`). Each kind applies its own Jones matrix: waveplate retardance, polarizer projection, PBS splitting (with the face convention `face_1..6` = ±X/±Y/±Z, `H_transmit_V_reflect`).

## The solver: an anchor-centric ray tracer (current)

- **The Kind Registry** (alembic 0086): the DB `kinds` table holds the metadata (name, domain, `op_set_name`, default_params, needs_aperture, wavelength_range_nm); **the code-side REGISTRY holds the op callables**, joined by `op_set_name`. A new kind can be created in the UI on top of an existing op.
- **Live: the anchor tracer** (`anchor_tracer.py`, Phase 9.2): a single loop with **no `switch(kind)`** — dispatch is a table lookup of each kind's **anchor op** (`anchor_ops/<kind>.py`, registered with `register_anchor_op(kind, op)`). An op is roughly `(rayIn, in_anchor, out_anchor, params, dynamic?) => BeamRay[]`, returning an array so it can branch (AOM orders, PBS transmit + reflect, ghosts). A `BeamRay` carries the chief ray plus independent qx/qy (astigmatism) plus the Jones s/p. Hits use ray-plane intersection (through `anchor.position`, perpendicular to `axisX`) with aperture clipping (see [anchors.md](anchors.md)).
- **Legacy (retired)**: the old **face-based** dispatch (`ray_tracer.py`'s `PhysicsOp(rayIn, faceIn, faceOut)`) was replaced by the anchor-based one when **0106 dropped faces/transitions**.
- **AOM Bragg**: `theta_B = asin(λ·f_rf / (2·v_acoustic))`, `theta_deflect(order) = order·2·theta_B` (the external-angle convention). **Order selection is geometric** (2026-08-14): the matched incidence angle for order m is `theta_in = −m·theta_B` (signed, measured against the acoustic axis), and each order carries its own `sinc²` mismatch factor — so the +1 and −1 matched positions are `2·theta_B` apart and the AOM has to be rotated to the corresponding side. The Bragg block in Object panel → Align (`utils/aomAlign.ts`) does the two-stage placement plus mrad fine-tuning. Detail in [aom-model.md](../aom-model.md).

## The state of the solver (important)

- **The backend anchor solver** (`anchor_tracer.py` + `solve_anchor_scene` in `solver.py`, endpoint `/api/v3/solver`, DB loading through `db_scene_loader.load_anchor_scene_from_db`) is **the only authoritative optical engine**. The beam you see in the lab is the backend anchor trace.
- The old legacy chain solver (`optical_solver.py` + `rf_propagation.py` + `optics_seq`'s solve_chain) was **deleted** in Phase 1 (around migration 0094); the Lab's "Run" button now goes through this engine too. RF graph propagation is handled by `rf_resolve.py` (see [cable.md](cable.md)).
- **The component preview probe (2026-06-12)**: the PHY Editor COMPONENT preview's probe beam also uses **the same anchor engine**, through the endpoint `POST /api/v3/solver/run-from-component` (`v3_solver.py`) and the loader `db_scene_loader.load_anchor_scene_from_component`. It assembles a scene from **a single Component's bindings** (in the **component frame**, with an identity SceneObject pose and no ObjectBinding delta / dynamic_sources / RF / power gating), traces the probe ray the caller supplies as the initial ray, and returns the same `labSegments` as run-from-db (including per-segment Jones). That is what lets the frontend draw **real polarization** per segment in the component preview (including non-reciprocal Faraday), replacing the old frontend face-probe approximation (see [rendering.md](rendering.md)).
- The TypeScript ray-tracing engine in the frontend's `optical/` (`ray-tracer-v3.ts` and friends, **face-based**) is a **parallel, not-yet-live** implementation: today only vitest references it and main.tsx cannot reach it, but it has full parity tests plus golden fixtures — **do not delete it as abandoned work**.

## Laser-source emission and Gaussian propagation (emit_laser_source.py)

An emitter does not wait for incoming light; it actively seeds the initial `BeamRay` (`emit_anchor_source_rays`). Beam propagation is governed by the **complex q parameter** (per axis, `qx` / `qy`, so astigmatism is supported) plus the **embedded-Gaussian** method. `laser_source` defaultParams (**only keys flagged in the Asset's `tunable_params`** can be overridden per instance through `SceneObject.dynamic_sources`; the tunable default is `nominalPowerMw` + `centerWavelengthNm`, with everything else decided by the Asset — see [data-model.md](data-model.md)):

- `centerWavelengthNm` (λ), `nominalPowerMw` (P — when the emit op reads dynamic values, `nominalPowerMw` takes priority over the legacy `powerMw` / `laserPowerMw` aliases, which is what makes per-instance power tuning take effect), `polarization` (Jones, in the anchor axisY/axisZ basis).
- `spatialModeX/Y.waistUm` (the waist w₀), `.mSquared` (M²), `.waistZOffsetMm` (the waist's offset along +axisX).
- `transverseModeType` (`"HG"` / `"LG"`) + `mode_index_1` / `mode_index_2` (HG = m/n; LG = p/l).

**Theory (embedded Gaussian, `emit_laser_source._q_at_waist_mm`)**:
- The seed is `q₀ = -z_offset + i·z_R` with **`z_R = π·w₀²/(M²·λ)`** — q carries the "embedded fundamental mode" whose divergence has already been magnified by M² (far-field half-angle `θ = M²λ/(πw₀)`), so it propagates correctly through each ABCD op automatically (a lens as `1/q'=1/q−1/f`, free space as `q+z`).
- **The real transverse width = (the embedded width derived from q) × `BeamRay.width_mult`**, where `width_mult = √(M²) × the mode factor` (LG: `√(2p+|l|+1)` on both axes; HG: x = `√(2m+1)`, y = `√(2n+1)`). `width_mult_x/y` propagates with the ray through `.replaced()`, then via `LabSegment.width_mult_*_at_start` → the solver's `to_dict` `widthMultAtStart` → the frontend `v3TraceAdapter`, which restores the width **independently per axis** (X ← qx, Y ← qy; since 2026-06-11 `beamMode.x/.y` and `waistAtStart/EndUm{,Y}` are all per-axis — y used to reuse qx, so beams were always round). TA mode matching (`misc_ops._mode_match_eta`) multiplies by the same factor. **Astigmatism rendering**: both the 2D beam-scope profile and the 3D optical link's **elliptical cone tube** consume this per-axis pair of widths (see [rendering.md](rendering.md)).
- **Limitation**: in this geometric cone, higher-order modes **only scale the equivalent width; they don't draw donut/lobe shapes** (a real ring needs a 2D complex-amplitude wave field, which this engine does not have). `waistZOffsetMm` flows to the frontend naturally through `Re(q)`, requiring no frontend change.

**The non-paraxial divergence correction (high NA / sub-wavelength waists)**: q-ABCD is paraxial (`z_R=πw₀²/(M²λ)`), so when `w₀→λ` (a fibre end face, a tight focus) the divergence becomes inaccurate. The approach: **keep q paraxial** (the chief ray and lens focusing are unchanged) and apply the correction only to the **width readout** —
- `s = M²λ/(πw₀)` (the paraxial divergence parameter = sinθ, rigorous); the **hard diffraction floor is `s≤1` ⇔ `w₀≥M²λ/π`** (NA = 1), with `s>1` evanescent, clamped and flagged past-limit.
- The far field uses `z_R_eff = z_R·√(1−s²)` (so the far-field slope → `tan(arcsin s)`); at low NA (s ≪ 1) → `z_R_eff≈z_R`, i.e. exactly back to paraxial.
- Helpers: `beam_ray.nonparaxial_fundamental_waist_mm` (backend) / `v3TraceAdapter.nonparaxialFundamentalWaistUm` (frontend, same formula). **M² must be available at readout time**, so `m2x/m2y` travel alongside `width_mult` through ray → `LabSegment` → `to_dict` (`m2AtStart`) → the frontend; `mode_factor=width_mult/√M²`. Application points: the optical-link cone widths and TA mode matching (`misc_ops._mode_match_eta`).
- **Fibre mode matching** will be connected to the same helper later (same high-NA problem, same solution).

## The transverse beam matrix Q — general astigmatism, Step 1 (2026-08-20)

`qx` / `qy` are a **scalar pair**, and a scalar pair can only describe astigmatism whose principal axes coincide with the element's own frame. Two places in the tree already carry that limitation in a comment: `anchor_ops/lens.py:_tilt_astig_focals` ("the q-tracer carries qx/qy independently and **cannot represent a rotated astigmatism axis**" — it drops the off-diagonal cross-astigmatism term of a tilted lens) and `solvers/generalized_abcd.py:apply_operator` ("cross-axis coupling on the q-parameter … is NOT modelled"). And it is not academic: `BeamRay` has **no transverse frame at all** — each op reads `qx`/`qy` against its OWN anchor's axisY/axisZ (`lens.py`: `qx ↔ axisY plane, qy ↔ axisZ plane`), and no op ever rotates them (`mirror.py` does not touch q, so folding the beam does not rotate its astigmatism frame). The engine therefore silently assumes every element's transverse axes are mutually aligned about the beam axis.

The closed object is the complex **symmetric** 2×2 beam matrix `Q` (three independent complex numbers), with `E ∼ exp(−i·k/2 · rᵀQ⁻¹r)`, propagated by the general-astigmatic ABCD law `Q' = (A·Q + B)(C·Q + D)⁻¹` over 2×2 blocks (Arnaud & Kogelnik). `beam_ray.py` now provides it:

- **`Mat2`** — minimal 2×2 complex algebra (`identity` / `diag` / `scalar`, `+`, `@`, `det`, `inverse`). Deliberately **not** numpy: a 2×2 closed-form inverse keeps `beam_ray` dependency-free and hot-path cheap, and makes the eventual TS mirror a transcription.
- **`QMatrix(xx, yy, xy)`** — `xx`/`yy` **are** the historical `qx`/`qy`; `xy` is the cross term they could not express. `xy == 0` ⇔ orthogonal ("simple") astigmatism aligned with the element frame.
- **`BeamRay.qxy`** (default `0j`) + `.q_matrix` / `.with_q_matrix()`. It rides through `replaced()` untouched, like `width_mult`.
- **`q_matrix_after_abcd(q, A, B, C, D)`** and **`q_matrix_principal_widths(q, λ) → (w_major, w_minor, azimuth)`**, the latter from the eigenvalues of `Im(Q⁻¹)` (`w² = −λ/(π·μ)`).

**Step 1 changes no behaviour, by construction.** Nothing writes a non-zero `qxy`; every op still drives the diagonal; and both helpers take an **exact scalar fast path** when their inputs are diagonal, reusing the historical expressions verbatim. Verified three ways: `tests/optical/test_q_matrix.py` (50 cases) asserts `==` — not `approx` — against `_q_after_abcd` and `gaussian_width_mm`; the full suite is green (593 passed / 3 skipped); and a live `/api/v3/solver/run-from-db` trace is **byte-identical** across the change.

Two things the tests pinned down that Step 2 must respect:

- **`_q_after_lens` is not bit-equal to the ABCD form.** It evaluates `q/(1 − q/f)`; the ABCD law evaluates `q/((−1/f)·q + 1)`. Algebraically identical, but the divide-by-`f` and the multiply-by-`−1/f` round differently and disagree in the last ULP for some inputs (`f = −75` with a strongly astigmatic q does). Step 2 must either keep `lens.py`'s own expression or accept ULP-level movement in the optical goldens — `test_lens_shortcut_agrees_only_to_ulp` exists so that is a decision, not a surprise.
- **A thin lens cannot change the spot shape.** Since `Q'⁻¹ = Q⁻¹ − P` and the power tensor `P` is real, `Im(Q⁻¹)` — and hence the intensity ellipse — is invariant across a thin lens no matter how the lens is rotated; only the wavefront turns. A rotated cylindrical lens shows its off-diagonal in the *widths* only after some free space (`test_thin_lens_leaves_the_intensity_ellipse_alone`, `test_rotated_cylindrical_needs_the_off_diagonal`).

### Step 2a — the frame (2026-08-20)

The frame turned out to need **no new field on `BeamRay`**. The Jones vector has the identical problem and it was solved long ago: `jones.beam_local_sp(direction)` derives a *canonical* transverse (s, p) basis from the propagation direction, and every direction change (lab↔body, a mirror bending the beam) re-expresses the Jones vector by the angle between the old and new canonical bases. **Q now lives in that same basis**, so it reuses that geometry verbatim rather than inventing a second one — the polarization frame and the astigmatism frame cannot drift apart.

New in `beam_ray.py`:

- **`q_rotate(q, phi)`** — `Q' = R·Q·Rᵀ` with exactly `rotate_jones`' `R = [[c, s], [-s, c]]`. `phi == 0.0` returns the input object untouched, so a scene whose elements are mutually aligned about the beam axis stays bit-identical.
- **`q_power_tensor(1/f_u, 1/f_v, phi)`** — the real symmetric focusing-power tensor of an element whose principal axes sit at `phi`. `1/f_v = 0` is a cylinder; equal powers give an isotropic P for which `phi` is irrelevant (asserted).
- **`q_after_thin_element(q, P)`** — `Q' = Q(I - P·Q)⁻¹`, i.e. `Q'⁻¹ = Q⁻¹ - P`.

New in `jones.py`, each the twin of the Jones function directly above it and sharing its angle: **`q_lab_to_body`** / **`q_body_to_lab`** (via the extracted `sp_rotation_*` helpers), **`q_rotate_into_new_frame`** (reflected/refracted rays), **`q_axis_to_lab`** (emitters whose `spatialModeX/Y` are defined against the anchor's `axisY`/`axisZ`), and **`q_beam_to_axis`** / **`q_axis_to_beam`** + `q_frame_angle_to_axis` (an op moving between the beam frame and its own anchor frame).

`tests/optical/test_q_frame.py` (32 cases) covers the algebra, the shared-convention guarantee (a polarization along Q's major axis stays along it across a frame change), and the payoff: **a 2× cylindrical Galilean telescope mounted at 0°/30°/45°/90°/115° produces an ellipse whose major axis tracks the telescope's own azimuth** — the case the scalar pair provably could not hold.

**2a is still behaviour-neutral**: the helpers exist but no op calls them yet, the suite is green (625 passed / 3 skipped) and the live trace is byte-identical.

### Step 2b — the wiring (2026-08-20)

Deliberately left as one atomic change, because a half-rewired engine is worse than an unrewired one: if the emitter starts publishing Q in the beam frame while `lens.py` still reads `qx` as "the axisY plane", the result is wrong in a *new* way rather than the old known way. 2b is: `anchor_tracer.py`'s two lab↔body conversion points; `emit_laser_source` (anchor frame → beam frame); `lens.py`'s three branches (thin, thick, cylindrical) rotating into the anchor frame and applying `q_power_tensor` — this also retires the dropped cross-astigmatism term in `_tilt_astig_focals`; the direction-changing ops `mirror.py` and `pbs.py` calling `q_rotate_into_new_frame` alongside their existing `rotate_jones_into_new_frame`; `misc_ops`/`fiber`/`aom`/`waveplate`/`polarizer` audited for frame correctness (none applies transverse power, so most need nothing); `qxy` serialised through `LabSegment` → `to_dict`; and the TS mirror in `frontend/src/optical/beam-ray.ts`.

**2b changes the trace by construction** — that is the fix — so byte-identity is not the test. What landed:

- **`anchor_tracer.py`** does the frame work for everyone, at two points. On the way in, free-space propagation (`Q' = Q + L·I`, diagonal-only and therefore commuting with rotation) then `q_lab_to_body`. On the way out, **one** `q_rotate_into_new_frame` from the incoming to the outgoing beam direction, then `q_body_to_lab`. Centralising the out-ray rotation means every beam-bending op — mirror, PBS reflection, AOM order, lens deflection — is handled without touching any of them.
- **`emit_laser_source`** (both the laser and the TA-ASE emitter) publishes Q through `q_axis_to_lab`, so `spatialModeX/Y` keep meaning "along the anchor's axisY/axisZ" and rolling an emitter's mount now rolls its astigmatism with it, exactly as it already rolled its polarization.
- **`lens.py`**, all three branches. Thin and cylindrical rotate into the anchor frame, apply `q_power_tensor`, rotate back; thick routes its isotropic blocks through the matrix law so an incoming off-diagonal survives. New `_tilt_astig_power_tensor` **restores the cross-astigmatism term** `_tilt_astig_focals` documents as dropped — same diagonal, plus the off-diagonal that a tilt at a non-principal azimuth actually produces.
- **Ops that build Q rather than transform it** — `fiber` (round mode: clears the inherited cross term) and the TA output in `misc_ops` — use `q_for_outgoing_frame`, which pre-rotates into the incoming frame so the tracer's single pass lands them exactly where intended.
- **`_mode_match_eta`** was the subtle one: it *consumes* Q, pairing it with `inputSpatialModeX/Y` and the hit offsets, all of which live in the anchor basis. It now rotates the seed in first. Missing this initially cost the TA its output entirely — a good demonstration that read sites matter as much as write sites.
- **`qxy` is serialised** through `LabSegment` → `V3LabSegment` → `qxyAtStart`.

**Verification.** 626 backend tests green. On the live scene, traced in-process against a pre-2b baseline of the same scene: **22 segments before and after, identical topology, identical power multiset, and the principal widths conserved to 4.4e-16 mm.** The entire difference is that **four segments now report a non-zero astigmatism azimuth** (0° → 45°, 45°, −45°, −90°) instead of silently claiming the frame axes. Their major/minor widths are untouched — the astigmatism was always at those angles; the engine used to misattribute it. That is exactly, and only, the class of error 2b exists to remove.

Two tests changed rather than broke, both because they asserted the old conflation: `test_oblique_beam_focuses_at_split_focals` (for a beam tilted in x-y the canonical s-axis is world +z, so the *tangential* focal belongs to qy, not qx) and `test_output_mode_honours_waist_offset_and_m_squared` (same swap). Both now assert the frame explicitly.

**A 0.004 mW branch that appeared to vanish was a false alarm, and the way it was run down is worth recording.** The before/after traces differed by one segment: a 3.46 mW ray that used to hit `TAPERED_AMPLIFIER0`'s `intercept_in` escaped instead, taking the TA's 0.004 mW output with it. Neither tracer rotation brought it back when stubbed to identity, and `intersect_anchor` is purely geometric (plane hit, `t >= t_min`, radial distance vs `aperture_mm`) — it never reads q — so the frame work could not be the cause. Instrumenting `nearest_anchor_hit` showed the TA's `intercept_in` sitting 397.478 mm off the ray, exactly the measured miss distance; a scene diff then pinned it: `TAPERED_AMPLIFIER0.yMm` had gone from `-453.248079` to `-55.769883` mid-session, with `properties.placedRelativeTo.recordedAt` stamped that same day. **The object had been moved in the viewer between the two captures** — the baseline was stale, not the code. Step 2b changes the trace *only* by the three frame re-expressions above; the topology is untouched.

Restoring `yMm` made the original baseline valid again, which is where the clean 22-vs-22 comparison above comes from. Lesson for the next comparison of this kind: the live DB scene is mutable while the frontend is open, so a trace baseline is only valid if the scene is known unchanged. **Diff the scene, not just the trace.**

### Step 2c — the readout tensors (2026-08-20)

Q was frame-correct after 2b, but `width_mult_x`/`_y` and `m2x`/`m2y` were still **scalar per-axis** values riding alongside it. They did not rotate, so after any non-trivial frame change the multiplier was scaling a different axis than the `q` it belongs to. Both are now symmetric tensors — `width_mult_xy` and `m2xy` join the diagonal, exactly the pattern `qxy` established.

- **`sym2_rotate(xx, yy, xy, phi)`** and **`sym2_eig`** in `beam_ray.py`. `sym2_rotate` returns its input untouched for `phi == 0` **or** for an isotropic tensor — the latter is exact rather than a shortcut (an isotropic tensor genuinely is the same in every frame), and it is why the live scene, where every beam has equal M² on both axes, moved not one bit.
- **`q_width_tensor(q, λ)`** gives the embedded width-squared tensor `W = -(λ/π)·Im(Q⁻¹)⁻¹`, and **`beam_real_widths`** returns the real `(w_major, w_minor, azimuth)` from `W_real = S·W_emb·S`. For a diagonal `S` and diagonal `W_emb` this is exactly the old per-axis `embedded_width × width_mult`; the difference is that both now turn together.
- **`BeamRay.rotated_frame(phi)`** rotates Q *and* both tensors in one call, plus `.width_mult_tensor` / `.m2_tensor` / `.real_widths()`. Every site that changes frame now goes through it — `anchor_tracer`'s three transitions, both emitters, the TA output, and `_mode_match_eta` — so the three can no longer be rotated by different amounts. That single-call discipline is the actual fix; the tensor algebra is just what makes it expressible.
- The jones-side helpers became **angles** rather than rotated values (`sp_rotation_lab_to_body` / `_body_to_lab` / `_between_directions` / `_axis_to_lab`), since the angle is what all three quantities share. The Q-only wrappers 2b had added (`q_lab_to_body`, `q_body_to_lab`, `q_rotate_into_new_frame`, `q_for_outgoing_frame`, `q_axis_to_lab`) were superseded and removed; `q_axis_to_beam` / `q_beam_to_axis` stay, used by `lens.py`, which transforms Q only — its in-and-out rotation is a round trip, so the multipliers are correctly untouched by it.
- `width_mult_xy` / `m2xy` are serialised as the `xy` key of `widthMultAtStart` / `m2AtStart`.

**Verification.** 653 backend tests (`tests/optical/test_readout_tensor.py` adds 27). The load-bearing one is `test_real_widths_are_frame_independent`: with an **anisotropic** multiplier — the case that used to break — the real principal widths are invariant under a frame rotation, paired with `test_rotating_q_alone_would_have_changed_the_answer`, which asserts the pre-2c behaviour *would* have moved them, so the invariant cannot pass vacuously. `test_output_mode_honours_waist_offset_and_m_squared` flipped from the gap this doc pinned open in 2b: `(m2x, m2y)` now reads `(1.0, 4.0)`, swapping in lockstep with `qx`/`qy`, i.e. M² stays attached to the axis it describes. On the live scene the trace is **byte-identical to 2b** once the new `xy` keys are excluded, and every readout cross-term is zero.

### Step 2d — the chief ray, and a 90° bug in the renderer (2026-08-20)

**The chief-ray kick now uses the full power tensor too.** `lens.py` applied `theta_y - y/f_y`, `theta_z - z/f_z` — the diagonal only — so a beam decentred in a lens tilted at an off-principal azimuth lost part of its deflection, the same cross term the envelope used to drop. It is now `theta' = theta - P·r` with `P = _tilt_astig_power_tensor(...)`, which reduces to the old expression exactly at normal incidence and whenever the incidence plane IS a principal axis. `_tilt_astig_focals` survives as the readable diagonal *view* of that tensor rather than a second derivation of it. Covered by `test_chief_ray_takes_the_full_power_tensor_not_just_its_diagonal` (asserts the axisZ kick a purely-axisY decentre now picks up) and a companion asserting the aligned case is untouched.

**And the payload/renderer mirror, which turned up a pre-existing bug.** `client.ts` now types `qxyAtStart` plus the `xy` key on `widthMultAtStart` / `m2AtStart`. While wiring it, the beam tube's transverse basis in `frontend/src/optical/beamChain.ts` turned out to be **rotated 90°**: it built its basis from `d × ŷ` and put `rx` — which comes from `qx`, i.e. the backend's **+s** axis — on it. But `beam_local_sp` defines **+s as world-up projected perpendicular to d**, and *up is +z*: **the three.js scene shares the lab frame's axes, both Z-up** (`optical/frames.ts`: "Three … uses the same axis convention as Lab"; `labToThree` is a pure scale with no axis re-map). So for a beam along +x the basis put `rx` on ±ŷ where it belongs on ẑ, and every astigmatic beam's ellipse was drawn a quarter-turn out. `beamChain` now mirrors `beam_local_sp` exactly, including its `|d·ẑ| > 0.999` fallback to +x̂, and orients on `makeBasis(principalX, direction, -principalY)` — the negation keeps the basis right-handed, since `principalX × direction = -principalY` and a reflection would invert the tube's normals. `beamChain.test.ts` pins the mapping (including the vertical-beam fallback, which is invisible for table-plane beams), the handedness, and that a circular beam stays circular.

### Step 2e — the azimuth through the frontend (2026-08-20)

The frontend models a beam as **two independent axes**, which is exact only while those axes coincide with the backend's beam-local (s, p) frame. Rather than teach it the matrix, the adapter now finds the beam's **own principal frame** and hands the existing per-axis model over in the frame where it is exact, carrying the leftover roll as one scalar.

One angle per segment is enough, and that is a physical fact rather than a simplification: every element in the tracer applies a *rotated diagonal* operator, so Q always has the form `R·diag(qa, qb)·Rᵀ`, and free space is `Q + L·I = R·diag(qa+L, qb+L)·Rᵀ` — the same `R`. **The principal axes do not turn between elements; only the widths do.** (A beam with genuinely general astigmatism, where `Re` and `Im` of `Q⁻¹` have different principal axes, *would* twist as it propagates. The tracer cannot currently build one.)

- **`frontend/src/optical/beamTensor.ts`** — a mirror of the backend's `sym2_rotate` / `sym2_eig` / `q_width_tensor` / `beam_real_widths`, plus `rotateCSym2` for Q. `principalAzimuthRad` takes the angle from the REAL width tensor (real symmetric, so `atan2` resolves the quadrant unambiguously) and returns **exactly 0** when there is nothing to rotate, which is what keeps every pre-existing payload bit-identical.
- **`v3TraceAdapter`** rotates Q *and* both readout tensors into that frame before deriving `waist0Um` / `waistZUm`, so all the downstream per-axis math is unchanged and now exact. `BeamState.azimuthRad` / `SegmentBeamMode.azimuthRad` carry the angle; `beamWidthsUmAtPathMm` returns it alongside the widths.
- **`beamChain`** builds the tube basis on the principal axes: `principalX = cos·sBeam + sin·pBeam`, oriented as `makeBasis(principalX, direction, -principalY)`. Zero azimuth reduces to the unrolled basis exactly, so it is a strict generalisation of the Step-2d fix, and the negation keeps it right-handed.
- **`BeamScopePanel`** samples the analytic profile through the inverse roll, so a cylindrical lens mounted at 45° draws a 45° ellipse instead of an axis-aligned one, and the plot title appends `· axes NN°` when the roll is non-zero.

**Verification.** 662 frontend tests (`beamTensor.test.ts` 16, `beamChain.test.ts` +3, `v3TraceAdapter.azimuth.test.ts` 7) and 656 backend, `tsc` clean. The adapter test is end-to-end: it rolls a known astigmatic Q by a known angle, asserts the angle comes back, and asserts the **principal widths are identical however the beam is rolled** — paired with a guard asserting the pre-azimuth behaviour *would* have got them wrong, so it cannot pass vacuously.

### Step 2f — settling the profile's absolute orientation (2026-08-20)

`BeamScopePanel` carried a standing "verify the analytic orientation in the UI" note against a hard-coded quarter turn, `sampleIntensity(y, -x)`. It is now **derived instead of assumed**, which settles the question without needing to eyeball anything.

Reading the pieces: `Heatmap` samples `sample(x, y)` with x screen-horizontal (right positive) and y screen-vertical (up positive), labelling the horizontal axis `transverse[0]` and the vertical `transverse[1]`, where `transverse` is the two world axes ⊥ to propagation in x < y < z order. `sampleIntensity` takes the beam's own principal coordinates. So the question is just: which display axis does the beam's +s land on?

| beam direction | +s | +p | `transverse` | fixed 90° |
|---|---|---|---|---|
| lab +x | +z | −y | x: `["y","z"]` | ✅ |
| lab +y | +z | +x | y: `["x","z"]` | ✅ |
| **lab +z** | **+x** | **+y** | z: `["x","y"]` | ❌ **quarter-turn out** |

`beam_local_sp` switches to its fallback reference axis when the beam runs along up, so +s jumps from `transverse[1]` to `transverse[0]` — and a fixed rotation cannot follow. Correct for every beam in the table plane, wrong for a vertical one, which is why it went unnoticed.

`optical/beamTensor.ts` now exports `beamLocalSp` / `transverseAxisLabels` / `displayToBeamFrame`; the panel projects the display axes onto the beam's (s, p) basis and then applies the azimuth roll. `beamTensor.test.ts` asserts, for all six axis directions, that **a beam wide along +s is drawn wide on the display axis LABELLED with s's world axis** — the precise statement of "the absolute orientation is right" — plus that the map reproduces `sampleIntensity(y, -x)` exactly for a beam along +x (why the old form survived) and provably does not for one along +z.

The only thing still unpinned is a *mirror*: for a beam along +x, +p is lab −y, so the horizontal axis increases leftward. An intensity profile is symmetric, so this is invisible unless the beam is decentred or in an odd-order HG mode.

`m2x`/`m2y` and `width_mult_x`/`_y` are **scalar per-axis** quantities and are *not* frame-transported, so after a non-trivial rotation they no longer line up with the Q they annotate. Harmless while both axes share an M² — true of every beam in the live scene — and wrong otherwise. The fix is to carry the width multiplier as a symmetric tensor and take the readout width from `q_matrix_principal_widths`. Pinned by an explicit assertion in `test_output_mode_honours_waist_offset_and_m_squared` so 2c flips it deliberately. The chief-ray kick in `lens.py` (`theta - y/f_y`) likewise still drops the cross term that `_tilt_astig_power_tensor` now restores for Q; that one moves ray positions, so it wants its own pass.

## Lenses and clear-aperture energy truncation (POP Stage 1, 2026-06-11)

Besides the `1/q'=1/q−1/f` ABCD, the lens op `anchor_ops/lens.py` (`lens` / `lens_biconvex` / `lens_plano_convex` / `lens_cylindrical`) now applies two attenuation factors to `power_mw` (`_lens_power_factor`, `lens.py:44`):

- **Clear-aperture clipping**: when the spot is wider than `anchor.aperture_mm` (a radius), its wings are blocked. The transmitted energy fraction uses the closed-form Gaussian **`T_ap = 1 − exp(−2a²/w²)`**, with `w = √(wx·wy)` and `a = anchor.aperture_mm`. **Alignment (2026-06-11)**: the chief ray does not necessarily hit the aperture centre — the op feeds the radial decenter `r_c=√(off_y²+off_z²)` from `hit.offset_y/z` into `gaussian_circular_aperture_fraction(w,a,r_c)`, and a decentred beam uses a **knife-edge model against the nearest aperture edge**: `T = ½(1+erf(√2·(a−r_c)/w))` (with the signed edge distance `s=a−r_c`; `r_c=0` degenerates back to the on-axis closed form). When the tracer builds the `aperture_truncation` descriptor it uses **the same** `r_c` (carrying an extra `decenterMm` field), so the `combinedFraction` shown in the scope equals the power the op actually removed.
- **Coating transmittance**: `default_params.transmittance` (defaulting to 1.0), the AR/Fresnel loss.
- `power_out = P_in · T_ap · transmittance`. **The single source of truth is `optical/aperture.py`** (`gaussian_circular_aperture_fraction` + `gaussian_width_mm`), mirrored by the frontend's `profileUtils.ts`; the tracer and the op both call it, so they can never diverge.
- **Backward compatibility**: an old lens asset with no aperture (`apertureMm=0`) or no transmittance gets a factor of 1.0 and unchanged power; an ordinary narrow beam (w ≪ a) gives `T_ap≈1`.

**Display**: the tracer records `{apertureMm, wEffMm, transmittedFraction, transmittance, combinedFraction}` in the "entering the lens" segment's `LabSegment.aperture_truncation` (`anchor_tracer.py`, only for `LENS_KINDS` with `aperture_mm>0`) → `solver.to_dict`'s `apertureTruncation` → `v3TraceAdapter` → BeamScopePanel showing "Aperture: X% through". **Note**: the descriptor sits on the *entering* segment (whose power is pre-truncation); the actual power drop shows up in the `power_mw` of the segment **downstream** of the lens (and flows automatically into the scope's `P` readout through `nominalPowerMwAtSource`).

- **This is the energy half**: the **diffraction (Airy) pattern** that the same truncation produces belongs to the wave field, which the q engine does not draw (see the "Limitation" above); the diffraction *pattern* is handled by a separate **POP field channel** (below), while the 3D scene beam stays a Gaussian cone. Polarization / RF / AOM / fibre all stay in the q channel.
- **The A230TM-B** (a Thorlabs asphere, `kind=lens_plano_convex`): `default_params.focalLengthMm=4.51` (the key the op reads — **not** the Object panel's `focalMm`), `clearApertureMm=4.95`, `transmittance=0.995`; the intercept anchor's `apertureMm=2.475` (= clearAperture/2, a radius).

### A cylindrical lens's axis is geometry, not a parameter (`cylindricalAxis` retired, 2026-06-12)

`lens_cylindrical_op` (`lens.py`) reads only `focalLengthMm` and `transmittance`, and applies the thin-lens kick **only along `intercept_in`'s axisY** (`y` / `θ_y` / `qx`), letting axisZ (`z` / `θ_z` / `qy`) pass straight through. So the cylinder's orientation is **already carried by the anchor geometry**:

- **axisY = the focusing (curved) axis**; **axisZ = the cylinder axis (no optical power, the flat one)**; by orthogonality both are **necessarily ⊥ axisX** (the optical axis = the intercept_in direction).
- To rotate the cylinder, **rotate intercept_in's axisY/axisZ** (about axisX) in the PHY Editor — no second anchor and no parameter needed.
- The old `cylindricalAxis: "x"/"y"` string **has been removed from the kind seed**: the live anchor tracer never read it (it always uses axisY) and it was a duplicate, potentially inconsistent source of truth beside the anchor frame. Only the retired `kindParams` path (`OpticalElementCreate` in `schemas.py`, `rayTrace.ts`) still carries it, and that is a dead path.

## Oblique-incidence astigmatism (beam not aligned to the lens, 2026-06-11)

When the beam axis is not parallel to the lens optical axis (the anchor's `axisX`), a thin lens is **astigmatic**. `_tilt_astig_focals` (`lens.py`) splits the focal length by the incidence angle α into tangential `f·cosα` (in the plane of incidence) and sagittal `f/cosα` (perpendicular to it), then projects the focusing-power tensor `diag(1/f_t,1/f_s)` back onto (axisY, axisZ) using the plane-of-incidence azimuth φ=atan2(θ_z,θ_y) and takes the **diagonal terms** → `f_y` applies to `qx` (the axisY plane) and `f_z` to `qy` (the axisZ plane), plus the corresponding geometric kicks.

- α comes from the slope in `beam_state_from_anchor_hit` (`tanα=√(θ_y²+θ_z²)`); at normal incidence (α = 0) → `f_y=f_z=f`, degenerating exactly to the symmetric thin lens (existing behaviour unchanged). The elliptical spot flows automatically into the beam scope and the 3D cone through the per-axis beamMode qx/qy, **requiring no new plumbing**.
- **Limitations**: (1) the projection's **off-diagonal cross terms** (skew astigmatism at φ≈45°) are discarded — the q tracer's qx/qy are independent and cannot represent a rotated astigmatic axis; (2) cosα has a floor of `_COS_INCIDENCE_FLOOR=0.5` (≈60°) so near-grazing incidence cannot collapse `f·cosα→0` (the same convention as `beam_ray._NONPARAXIAL_S_FLOOR`); (3) it applies **only to the thin-lens branch** — the thick-lens ABCD and cylindrical lenses do not (that would need per-surface tilt, not implemented); (4) off-axis aberrations such as coma are non-paraxial geometry that the q tracer does not model (as in the "Limitation" above).

## Decentred truncation (the beam misses the aperture centre)

The chief ray does not necessarily hit the aperture centre: both the op and the tracer descriptor feed the radial decenter `r_c` from `hit.offset_y/z` into `gaussian_circular_aperture_fraction(w,a,r_c)` (see "Clear-aperture clipping" above), a decentred beam uses the **knife-edge model** `T=½(1+erf(√2·(a−r_c)/w))`, and the descriptor carries an extra `decenterMm` for display. **Why not `exp(−2(r_c/w)²)`**: the old form treated the lens as "a pinhole at decenter r_c" and used the Gaussian intensity at that point as the transmittance, which wrongly zeroed a beam that is decentred yet entirely inside a large aperture (e.g. `r_c=8.76 < a=12.7` with `w≈1` → `≈e⁻¹⁶²`) when the true 2D integral is ≈1.0. The knife-edge model instead looks at **how far the beam edge is from the aperture edge** (`a−r_c`): fully inside (`a−r_c≫w`) → ≈1, beam centre exactly on the rim (`r_c=a`) → ½, beam centre several w outside → 0. **Limitation**: a decentred Gaussian through a round aperture has no closed form, so this is an approximation matching the frontend's `profileUtils.ts` (it clips only against the near edge and does not model far-edge vignetting when `w≳a`); a large decenter (`r_c>a+3w`) is zeroed outright.

## The thick-lens model (short focal lengths / aspheres, 2026-06-11)

A thin lens collapses the front and back principal planes H/H' into one point; for a short-focus lens like the A230TM-B with **T/f≈0.6** (2.75 mm centre thickness, 4.51 mm EFL) the H–H' separation is millimetres — a large fraction of the focal length — so a thin lens puts the focus millimetres off. `lens_anchor_op` therefore **dispatches on parameters** (`_is_thick`, `lens.py`): if the asset's `default_params` has `radiusFrontMm` + `refractiveIndex` + `centerThicknessMm` it uses the **full air→air thick-lens ABCD**; otherwise it falls back to the thin lens with `focalLengthMm` (backward compatible, no new kind).

- **Why one anchor rather than two surfaces**: the tracer propagates q through **air** between anchors (`q+=t_lab`), so two real surfaces with glass between them would be propagated as air → wrong. A single anchor applying the **whole air→air ABCD** (with the refractive index living only inside the matrix coefficients, so q's boundaries are air on both sides) avoids that.
- **The ABCD** (`_thick_lens_abcd`): `P1=(n−1)/R1`, `P2=(1−n)/R2` (a flat surface has R=∞ → P=0), `τ=d/n`; `M=[[1−P1τ, τ],[−(P1+P2−P1P2τ), 1−P2τ]]`, `EFL=−1/C`. The sign convention matches the retired `thorlabs_la1509_b.json` `matrix5x5` (golden test with R=51.5/∞, n=1.5168, d=3.6). `q'=(Aq+B)/(Cq+D)` is applied to qx/qy; `apply_abcd_state` (`anchor_tracer.py`) applies the geometry (y, θ).
- **Geometry**: the `intercept_in` anchor sits at the **front vertex**; the op moves the outgoing ray's origin to the **back vertex** (anchor + d·axisX, signed) → so the focus lands at `back vertex + BFL` (physically correct) rather than the thin lens's `anchor + f`. The d-long segment inside the glass is not drawn (cosmetic).
- **Aspheres**: paraxially only the **vertex radius of curvature** matters; conic and asphere coefficients affect only aberrations (which the q tracer does not model).
- **The A230TM-B parameters come from a datasheet-equivalent fit**: the radii are not published, and deriving R1 from EFL cannot reproduce the working distance (it is not a simple plano-convex). Instead **EFL=4.51 + BFL=WD=2.53** (with n and d known) are solved for an equivalent (R1,R2): `P1=(1−BFL/EFL)/τ` → `R1=(n−1)/P1`, then P2 from `1/EFL` → R2. **EFL and BFL are independent of n** (the fit absorbs n), so n only sets the equivalent radii and does not move the focus. The A230TM-B asset stores `radiusFrontMm=2.3244`, `radiusBackMm=10.308`, `refractiveIndex=1.59`, `centerThicknessMm=2.75`.
- **Anchor position calibration**: the focus is only correct if the anchor sits at the **physical front vertex**; if the GLB origin puts the anchor elsewhere, the focus shifts as a whole → adjust the anchor z after visual verification.
- **POP is unaffected**: `/api/v3/pop` only computes the focal-plane Airy pattern (using EFL to set the first null and the scale) and does not place z, so the thick lens does not break POP.

## The POP field channel: lens focal-plane diffraction (Stage 2, 2026-06-11)

A **scalar 2D complex-field engine** that lives **in parallel with, and does not replace,** the q tracer. It turns a beam truncated by a finite clear aperture into the focal plane's **Airy rings** (something the q channel cannot draw).

- **The engine**, `optical/pop_field.py`: `PopField` (an N×N complex numpy field + pitch + λ). Operators: `seed_gaussian` / `seed_plane_wave`, `apply_circular_aperture` (a hard truncation → seeding the diffraction), `apply_thin_lens` (`exp(−i k r²/2f)`), `propagate_asm` (**angular-spectrum** free-space propagation, exact in near and far field, with evanescent components zeroed), `focal_plane` (a lens as the exact Fourier transform from front to back focal plane, output pitch = `λf/(N·pitch_in)`, a uniform round aperture giving the Airy first null at `1.22λf/D`), `radial_profile`, `downsample_intensity` (a **centre crop** to k·out_n followed by block averaging → keeping the axis in the middle of the output; a corner crop would shift the Airy peak, a bug that was actually implemented once).
- **The bridge**, `optical/pop_pass.py`: `lens_focal_airy_pattern(w_at_lens_mm, aperture_mm, f_mm, wavelength_nm)`. The geometry (beam radius w at the lens, aperture radius a, focal length f) is **supplied by the q channel, not recomputed here** (the frontend already knows w from `gaussianWidthMm(q)`). The flow: seed a Gaussian of width w at the lens → hard-truncate at the aperture → `focal_plane(f)` → crop to ±6 Airy nulls → downsample. It returns `{size, halfExtentUm, pitchUm, firstNullUm, clipFraction, intensity[peak-normalized], diffractionLimited}`. v1 limitations: a flat incident phase (incident wavefront curvature is ignored, since the rings mostly come from the truncation) and a single-lens focal-plane view.
- **The endpoint** `POST /api/v3/pop` (`routers/pop.py`, **on-demand only**, never part of the `/api/v3/solver` live trace): body `{wAtLensUm, apertureMm, focalLengthMm, wavelengthNm, gridN?, outN?}` → the payload above. The frontend calls it when the beam scope probes downstream of a truncating lens.
- **Physical verification** (`tests/optical/test_pop_field.py` + `test_pop_pass.py`): a round aperture's focal plane is Airy (first null within 8% of `1.22λf/D`, and rings confirmed present); free-space Gaussian `w(zR)=w0√2` (within 6%); the energy fraction of a Gaussian through an aperture equals Stage 1's `1−exp(−2a²/w²)` (within 3%). A radial cut from the live A230TM-B endpoint confirms a central bright spot → dark ring → secondary ring.
- **Stage 3 — DONE 2026-06-11**: `BeamScopePanel` finds that lens's `apertureTruncation` (which carries `focalLengthMm`) → calls `POST /api/v3/pop` → bilinearly samples the returned intensity grid into the existing `Heatmap` (replacing the analytic `sampleIntensity`), with the title marked "diffraction (POP) · focal plane". The geometry (beam radius w at the lens, aperture, focal length, λ) all comes from the q channel's segment descriptor.
  - **Only shown near the focal plane (fixed 2026-06-11)**: POP is a **focal-plane** Airy pattern and is only meaningful near the focus. `truncLens` picks the lens whose focal plane (`lensZ+EFL`) is nearest the probe, and returns a pattern **only when `|probe.z − focalZ| ≤ EFL`** → otherwise `popPattern=null` and it falls back to the **z-dependent analytic profile** (without this, probing far downstream kept showing the same fixed focal-plane image regardless of probe z — the bug the user reported). The POP focal-plane view also does **not** apply the analytic profile's 90° rotation / world-axis labels (see [rendering.md](rendering.md)).
- **Not done yet**: a detector image plane; an astigmatic POP field (v1 seeds a circular `w_eff`, and the focal-plane Airy is dominated by the round aperture and so is nearly circular anyway); incident wavefront curvature; and **arbitrary downstream planes** (option B: a converging lens's rings only exist within ±the depth of focus (~3 µm) of the focus and are a smooth spot away from it; plus a millimetre-scale near field with a ~3000× aperture-to-focal-spot ratio is a hard sampling problem → deferred).

## Beam splitters: PBS / Glan / non-polarizing cubes (beam_splitter, 2026-06-11)

The op is in `anchor_ops/pbs.py` (`register_anchor_op` registers both `pbs` and `beam_splitter`), with a single anchor `intercept_face` (axisX = the coating/cut normal, axisY = the s reference, axisZ = the p reference). Each hit **returns two branches**:

- **Transmitted (p, extraordinary)**: direction = `ray.direction` (straight through, not relying on axisX — so a Glan's cut normal being ~38° off does not deflect it); slab `B = L/n_e`.
- **Reflected (s, ordinary)**: direction = mirrored about axisX, `d − 2(d·axisX)axisX`; slab `B = L/n_o`.

**The slab refractive index is per branch**: the transmitted e-ray uses `refractiveIndex_e` and the reflected o-ray uses `refractiveIndex_o`; an ordinary PBS cube that sets only the isotropic `refractiveIndex` makes both branches fall back to the same value (`_pick_index`, with key order `refractiveIndex` before `refractiveIndex_e/o`). The length comes from `cubeSizeMm` or `lengthMm`.

**Finite extinction (leakage)**: `att = 10^(−ER_dB/10)` is the power fraction of the rejected polarization that leaks into a port, and it is **energy conserving** (the two exit fractions of each polarization sum to 1): the transmitted port = `(1−att_s)·E_p + att_p·E_s`, the reflected port = `(1−att_p)·E_s + att_s·E_p`. `extinctionRatioPpDb` is the transmitted P port (s leakage), `extinctionRatioSpDb` the reflected S port (p leakage); **the values are real dB** (100000:1 → 50 dB). A missing parameter ⇒ att = 0 = an ideal perfect splitter (ordinary cubes are unaffected).

**Non-polarizing cubes (`polarizing: false`, 2026-08-18)**: the op used to ignore the flag entirely and always split by polarization, so a Thorlabs BS0xx cube fed **pure s** sent 100 % out the reflected port and **nothing** out the transmitted one — the beam looked like it had simply vanished through the cube. An explicit `polarizing: false` now derives the same `att_p` / `att_s` from the **split ratio** instead of from the extinction ratios (`_nonpolarizing_atten`): `att_p = T`, `att_s = 1 − T`, which drops straight into the branch formulas above and scales **both** Jones components by `√T` on the transmitted port and `√R` on the reflected one — an intensity split with the polarization state untouched. `splitRatioTransmitted` is the transmitted power fraction (0.9 for a 10:90 R:T cube like BS041); missing / out of range ⇒ 50:50. The gate is an **explicit** `false`, so a missing key keeps the polarizing default and no existing asset changes behaviour. Coating **absorption is not representable** — this path is energy-conserving by construction, so a cube specced at T = 87 % / R = 7 % is modelled at its nominal 10:90. Test: `test_beam_splitter_nonpolarizing.py`.

**Splitting is referenced to the polarizer's own orientation (the plane-of-incidence frame, 2026-06-12)**: splitting is **not** done in the world-up beam-local s/p frame; the incoming Jones vector is first rotated into **the polarizer's own plane-of-incidence frame**: `s_glan = dir × axisX` (⊥ the plane of incidence = the s polarization of the reflected o-ray) and `p_glan = dir × s_glan` (the transmitted e-ray). `_glan_frame_phi` computes the signed angle φ from beam-local s to `s_glan`, `rotate_jones` rotates the Jones vector in for the split, and the two outputs are rotated back into beam-local (`pbs.py`). **Why**: an isolator's exit Glan is rotated **~45° about the optical axis** relative to its entrance Glan — the old code split both in the same beam-local frame, so the exit Glan would **transmit** the (Faraday-rotated) component it should have **reflected**. For a single horizontally mounted PBS, `dir×axisX ≈ beam-local s` → φ≈0 and nothing changes (backward compatible); at near-normal incidence (beam ∥ axisX, a degenerate plane of incidence) it falls back to the raw beam-local frame. Test: `test_pbs_axis_referenced.py` (a rotated Glan must fully reflect polarization along its own s axis). **The reflected branch still keeps the incident beam-local frame** (re-basing after a direction change is a pre-existing approximation, left untouched). Related: [the polarization frame of passive ops](#) — see the memory `polarization_frame_convention` (PBS is now orientation-referenced, but faraday and the seeded TA still need the same treatment).

The Glan-Laser prism assets inside an isolator **carry the `beam_splitter` kind and use this two-branch op**, not `glan_polarizer` (which transmits only, and whose op deflects the transmitted direction along the cut normal → broken for Glan geometry, see kinds.md and the code comments). The full parameter set is in [kinds.md](kinds.md) (beam_splitter's defaultParams *is* exactly what this op reads; there are no optionalParams).

**Debugging: "the transmitted polarization is vertical / impure" ≠ a frame bug (diagnosed 2026-06-12)**. An isolator's forward light is *supposed* to **pass through both Glans** (isolation only happens on the return trip, where glan1 reflects the light away), so seeing glan2 "transmit" in Object Sense / Optical Link is correct. If the transmitted light shows as **vertical and seemingly impure**, the root cause is usually that **the input polarization lies on glan1's reject (o-ray) axis**: glan1 reflects all of the main power out the side, and what continues forward is only the leakage `E_s·√att_p` defined by `extinctionRatioPpDb` (`pbs.py:162`, `att_p=10^(−Pp/10)`, so Pp = 50 dB → 1e-5) — **purely s (vertical)** but with ≈0 power. After the panel normalizes, it still draws a full-strength line with a polarization label, which is easy to misread as "transmitting nicely". Pushing `Pp→∞` only drives the vertically incident transmission to **zero** (it does not turn horizontal). The fix is upstream: align the laser's `polarization` (or rotate glan1 about the optical axis) to glan1's transmit (p) axis. Detail in the memory `isolator_glan_input_pol_gotcha`.

## The Faraday rotator (non-reciprocal polarization rotation, 2026-06-12)

The live op is `faraday_anchor_op` in `anchor_ops/misc_ops.py` (single anchor `optical_center`). **`kinds/faraday_rotator/physics.py` is retired face-based legacy that live code never reaches** (though its registry test `test_faraday_rotator.py` is still green). The op does two things: pass straight through the slab (`B=L/n`; q advances, no focusing, power unchanged) and rotate the Jones vector by `rotationDeg` (45° by default).

- **Non-reciprocity comes from signing by the anchor's axisX (`misc_ops.py:53`)**: the rotation is fixed to the lab B-field axis (= the rod's optical-axis anchor `axisX`), **not** the beam-local frame. `beam_local_sp` keeps ŝ and flips p̂ when the direction reverses, so a "direction-independent fixed matrix" is read as `R(−θ)` on the return trip and **cancels** the outbound rotation → degenerating into a reciprocal optical rotator and breaking the isolator (the pre-2026-06-12 bug, which the user observed as "the round trip cancels out"). The fix: `fwd = sign(direction·axisX)`, so out and back have the same handedness in the lab → a round trip accumulates **2θ** (45° + 45° = 90°, which the crossed polarizer then blocks on reflection).
- **The rotation handedness was reversed on 2026-06-12 (by request)**: `θ ← −rotationDeg·fwd` (previously `+rotationDeg·fwd`), so forward now rotates by −rotationDeg about axisX, both directions are `R(−θ)`, and a round trip is **−2θ**. **The non-reciprocity is unchanged; only the sense of rotation flipped**; the op-level contract tests' signs were updated to match.
- **The matrix** (with the `rotate_jones(+θ)` convention): `E_s' = cosθ·E_s + sinθ·E_p`, `E_p' = −sinθ·E_s + cosθ·E_p`.
- **Op level vs the whole chain**: a single op call only ever sees `±θ` (opposite signs forward and reverse); the full 2θ non-reciprocity only emerges once the tracer re-bases the Jones vector at the reflection. Op-level contract tests: `tests/optical/test_faraday_anchor_nonreciprocal.py`.

## The EOM: phase retardance and Mach-Zehnder intensity (extended 2026-08-20)

The live op is `eom_anchor_op` (`anchor_ops/misc_ops.py`), fired only by `intercept_in`. **Two axes that vary independently** — what the drive does, and where the light goes:

| `modulationKind` | what the drive does |
|---|---|
| `phase` | Retardance `δ = π·V/Vπ` on the slow Jones component. Polarization changes, power does not (bar the insertion loss). |
| `amplitude` | A Mach-Zehnder: the two arms have **already interfered inside the device**, so the drive lands on **power**, not on the Jones phase. `φ = π·(V_rf/Vπ_rf + V_bias/Vπ_bias)`, `T = IL·(1 + m·cos φ)/(1 + m)` with `m = (r−1)/(r+1)`, `r = 10^(extinctionRatioDb/10)`, `IL = 10^(−insertionLossDb/10)`. |

The `(1+m)` normalisation is what makes the two params mean their datasheet meanings: **T peaks at exactly IL** (insertion loss is quoted at peak transmission) and bottoms out at **IL/r** (peak÷null is exactly `extinctionRatioDb`).

**`driveVoltageV` / `biasVoltageV` are the kind's two `stateParamKeys` (2026-08-20)** — real params with a baseline on the asset, read through `ctx.params`, i.e. `{**asset.default_params, **dynamic_sources}`, so a per-instance value overrides the baseline under the normal ownership rule. Until then they were read from `ctx.dynamic` **only**, and since they were not `default_params` keys, `tunable_params` had nothing to point at and no UI could set either one — the Object panel simply had no field. Note they still do **not** come from the RF graph: the `rf_in` anchor the kind declares (optional, min 0) is cable-routing only, exactly like the AOM's.

**Align: per END, not per body (2026-08-21).** `eom`'s `alignVariant` is now `"none"` and it is out of `OPTICAL_ALIGN_KINDS` — a pigtailed modulator's two ports are FC/APC connectors on flexible pigtails, so each is aligned on its own (Object panel → Align → **Align End A / End B**) while the housing stays bolted down. The mechanism, and why an ObjectBinding delta is the right place to persist it, is in [component.md](component.md); alembic `0132_eom_per_end_align` resyncs the kind row. `alignToleranceMm` stays 25 — the per-end UX uses the same field.

**Polarization: a guided modulator is single-polarization (2026-08-20).** `_eom_guided_polarization` keeps only the component on `intercept_in`'s **axisY** — the TM / modulated axis, which the anchor's `fastAxis` role already reserved, and which for a pigtailed device is **derived from the PM key of the connector bound at that port** ([component.md](component.md)) — and floors the orthogonal one at `polarizationExtinctionRatioDb` (a POWER ratio, so 10^(−PER/20) on the field). The output is linear on that axis, re-expressed in the **exit** anchor's frame so a device whose two ports are not parallel still hands back a correct Jones vector; power is scaled by |E_out|²/|E_in|², the same Malus bookkeeping `polarizer_anchor_op` uses. The gate is `_eom_is_waveguide` = `modulationKind == "amplitude"` (an MZ always is a waveguide) **or** `fiberPigtailed`; a bulk crystal in a mount stays a pure retarder and is never filtered. In the waveguide **phase** case the drive becomes a **common** phase on the single guided mode rather than a retardance between two components — there is only one component left to retard.

| `fiberPigtailed` | where the light goes |
|---|---|
| `false` | `_slab_passthrough` — the beam keeps its incoming tilt / offset and leaves from **`intercept_in`** with q advanced by `lengthMm/refractiveIndex`. The pre-2026-08-20 behaviour, unchanged. |
| `true` | The light is **guided** across the package, so the output is re-emitted at **`intercept_out`** as the pigtail's fundamental mode: waist `coreMfdUm/2` **on** the exit face, direction = that anchor's axisX, incoming tilt erased, `qxy=0`. Same contract as `fiber_anchor_op`; a missing `intercept_out` returns `[]` (malformed asset) rather than silently emitting from the entry port. |

**Why the pigtail branch had to exist at all**: the anchor tracer propagates `q += t_lab` across every gap, so a slab passthrough would have diffracted a ~5 µm mode across the whole 130 mm package and handed the output pigtail a metre-wide beam — i.e. the trace would report ≈0 power through a part whose real insertion loss is 3.5 dB. Note the corollary: **the guided path contributes no `path_length_mm`** in v1 (the free-space gap between the two anchors is not traversed either), so an interferometer built around a pigtailed part has no internal optical length yet.

**What v1 does not model** (each would need a new param or a new op, none of them silently wrong — just absent): no Marcuse overlap at the modulator's own input face (the 0.125 mm anchor aperture gates a gross miss, and `insertionLossDb` is the fibre-to-fibre datasheet number that already contains the internal coupling); no RF bandwidth or transit-time rolloff (Vπ is the single quoted value, so the S21 curve on the label is not represented); no bias drift. Op-level tests: `tests/optical/test_eom_mz.py` (14 cases, including the polarization ones — note the fixture's anchor axisY is body +Z **because that is what the real device authors**, and for a +X beam that is exactly the beam-local s axis, so `make_beam_ray`'s default Jones launches on-axis).

## The RF tracer

RF is **not** a ray tracer — there is no wavefront, Jones vector or q. It runs a **graph BFS** over a port adjacency graph, carrying `RfSignalState{frequencyMhz, vpp, cumulativeGainDb, saturated, …}`. Constants: `AD9959_VPP_FULL_SCALE=1.0V`, `RF_LOAD_Z=50Ω`, `P=Vpp²/(8Z)`. The AOM is a **hybrid** — simultaneously an optical component for the ray tracer and an RF sink for the RF tracer; RF reaches it through the BFS into `signalAtPort[(aom,"rf_in")]`, and the AOM's RF setting resolves in the priority order **dynamicSources (manual) > the RF tracer > defaultParams.centerFreqMhz**. The timing side of the RF chain (AD9959 channels, PPG) is in [timing.md](timing.md).

## The tapered amplifier (design locked 2026-05-31, four-factor model 2026-06-01)

A semiconductor gain chip amplifying a seed. Locked decisions: forward A→B only; ASE emitted only when there is no seed (option 6b). The op is in `anchor_ops/misc_ops.py` (`tapered_amplifier_anchor_op`), with the representative asset `toptica_boosta_pro` (face A the seed at −z, B the output at +z).

**The gain axis = the anchor's `axisY`** (replacing the old `gainAxisDegBodyLocal` angle parameter): both faces `intercept_in` / `intercept_out` are marked `needsFastAxis`, and axisY is editable in the PHY Editor. The amplification is set by four physical factors, with coupled power `P_coupled = P_in · frac_TE · η_mode`:

1. **Polarization (the TE selection rule)**: `_jones_in_axis_basis()` rotates the incoming Jones vector into the anchor's (axisY, axisZ) basis and takes `frac_TE = |E_axisY|²/|E|²`. Only TE (∥axisY) is amplified and TM sees almost no gain; the output is linearly polarized along axisY with finite extinction (`polarizationExtinctionDb`).
2. **Seed intensity (gain saturation)**: `P_out = P_sat·ln(1 + (P_coupled/P_sat)·(G0−1))` with `G0=10^(smallSignalGainDb/10)`, clamped to `outputPowerMaxMw`. A weak seed → linear, poor extraction, high ASE; a strong seed → saturated, maximum output.
3. **Mode matching (the overlap integral)**: `_mode_match_eta()` computes the facet waist from the seed's q parameter (`w²=λ|q|²/(π·Im q)`) and takes a separable 2D Gaussian overlap with the waveguide mode `inputSpatialModeX/Y.waistUm` plus the hit's transverse offset. The output transverse mode is reshaped to `outputSpatialModeX/Y` — **all three `GaussianMode` fields, since 2026-08-19**: `waistUm` sizes the mode, `waistZOffsetMm` places the waist relative to `intercept_out` (`Re(q) = -waistZOffsetMm`, so an axis the chip's collimator does not correct keeps a *virtual* waist far off the facet), and `mSquared` sets both divergence (via q's M²-reduced z_R) and readout width (`width_mult = sqrt(M2)`, TEM00 facet), and is carried on as `m2x/m2y`. Until then the op used a 2-arg `_q_at_waist_mm(waistUm, lam)` that silently dropped the offset and M², pinning every TA output to an M²=1 waist exactly on the facet.
4. **Current-driver quality**: `driverQualityFactor∈[0,1]`, a steady-state extraction-efficiency penalty (1.0 by default). **Dynamic effects are out of scope**: α-parameter AM→PM noise, self-focusing/filamentation and M² collapse are time-domain / M²-aware phenomena (BeamRay has no M² field and the trace is steady state) → they belong to the time-domain module (see [timing.md](timing.md)).

New parameters: `polarizationExtinctionDb`, `driverQualityFactor` (a frontend interface plus kind defaultParams; the op defaults gracefully for older assets). Known bug: the op reads `smallSignalGainDb` while older assets store `gainLinear`; still to be unified.

**Output geometry comes from `intercept_out` (2026-08-18).** The op used to build its outgoing ray with `_slab_passthrough`, i.e. from **`intercept_in`**, advanced by `lengthMm/n` along the *incoming* direction — `intercept_out` was never read, so the amplified beam started inside the chip and sailed on through the housing (the anchor tracer has no solid geometry to stop it). Now `tapered_amplifier_anchor_op` (`anchor_ops/misc_ops.py:196`) looks up `intercept_out` on `ctx.asset.anchors` and emits from that anchor's **position** along its **axisX** (the outward face normal), adding the facet-to-facet separation to `path_length_mm`. Invariants:

- The waveguide sets the exit direction, so the seed's incidence does **not** steer it — a side-output / shaped TA whose two facets sit at any angle works correctly.
- The output is placed on-axis at the facet (the seed's transverse offset is dropped — the amplified beam takes the waveguide's mode), and `origin` is the anchor position **verbatim**, which makes the self-intersection `t` exactly `0.0` and therefore rejected by `intersect_anchor`'s `t_min` — no epsilon nudge.
- The output Jones is referenced to the **output** anchor's axisY (`gain_anchor`), not the input anchor's.
- Assets carrying no `intercept_out` keep the old slab passthrough, so un-migrated single-anchor rows still trace.

**ASE emits per facet, and the measured tables are live (2026-08-18).** `emit_ta_ase_rays` (`anchor_ops/emit_laser_source.py:202`) previously fired **both** facets off `intercept_in` along ±axisX; forward now leaves `intercept_out` and backward leaves `intercept_in`, each along its own outward normal (single-anchor assets keep the legacy ±axisX pair). Per-facet power resolves in order: the flat `aseForwardMw` / `aseBackwardMw` override → `aseSamples` interpolated at `driveCurrentMa` → the nested catalog default `ase.powerMw`. Seeded gain likewise prefers `gainSamples`: `ta_forward_power_mw()` interpolates the measured `(inputPowerMw × driveCurrentMa) → forwardPowerMw` table and falls back to the closed-form `ta_saturated_power_mw()` when no table is configured. Both interpolators (`ta_ase_table_mw` linear-with-clamp, `ta_gain_table_mw` inverse-distance over the 4 nearest samples) **mirror the frontend's `interpolateAse` / `interpolateTaGain`** so the TA panel's operating-point readout and the traced beam agree — keep the two in step.

⚠ **These tables must live on `Asset3D.default_params`, not `PhysicsElement.kind_params`.** `db_scene_loader` builds every tracer slot from `default_params ⊕ dynamic_sources` (`kind_params` is read only for the synthesized fiber slot), so a TA configured solely through the TA panel's PhysicsElement is invisible to the physics — the symptom is a beam that ignores your gain / wavelength / ASE numbers entirely. Decision 6b is unchanged: a **seeded** TA still emits no ASE, so `gainSamples.backwardPowerMw` is stored but not yet emitted.

**Each facet is tagged and can be hidden (2026-08-20).** `emit_ta_ase_rays` returns `(ray, emitter_id, source_id, emission_key)` with `emission_key` = `"forward"` / `"backward"` (the laser emitter uses `"main"`), and the tracer stamps it on every `LabSegment` down the chain — that is what lets the frontend colour the two facets independently. The same loop honours `SceneObject.properties.emissionVisuals[<key>].visible`: a facet the user unticked on the TA's **Visualization** card is **never emitted**, so downstream optics stop reflecting it too, rather than being merely hidden at draw time. The slot carries those overrides as `V3AnchorBindingSlot.emission_visuals`, populated by `db_scene_loader`. `emit_anchor_source_rays` applies the same gate to a `laser_source`'s `"main"`, right after the instrument-power check, so the laser card's Show toggle behaves identically. (Colour is presentation-only and stays a frontend concern.)
