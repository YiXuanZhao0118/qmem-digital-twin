- ~~**A fibre rendered at the origin instead of at its endpoints.**~~ **Fixed 2026-08-21.** `createFiberSplineObject` reads only `SceneObject.properties.fiberNodes` then `Component.properties.fiberNodes`, and falls back to a hard-coded **0→300 mm** straight run when it finds neither — but a freshly instantiated patch cable keeps its endpoints ONLY in the fibre PhysicsElement's `kindParams.endA/endB` (what Align End A/B writes and what the backend's `_synth_fiber_slot` traces), and **nothing writes `properties.fiberNodes` until a node is edited**. - ~~**A fibre Component with TWO SceneObjects silently edits the wrong cable.**~~ **Fixed 2026-08-21.** Fibre node editing was keyed on **componentId** — `enterFiberEdit(componentId)`, and `updateFiberNodes` / `insertFiberNode` / `removeFiberNode` each resolved their target with `objects.find((o) => o.componentId === componentId)`, i.e. the FIRST match — so two patch cords instantiated from one catalog Component shared an edit target and the second could not be shaped at all. **The parts library reproduced it through normal use**: `AssetLibraryPanel`'s **+** calls `ensureObjectForComponent(componentId)`, which rejects `rf_cable` / `sma_cable` / `programmable_pulse_generator` outright but happily places a **second** `fiber` object on the same catalog Component. Observed live that day on `Fiber PM PC-APC` (`FIBER0` + `FIBER1`) and `Fiber PM APC` (`FIBER1` + `FIBER2`); the earlier `FIBER_IN` / `FIBER_OUT` collision was worked around by cloning the Component per cable, which is no longer necessary. The fix is the one this entry recommended — key the edit on objectId the way `rf_cable` already does — applied across all three layers that could each pick the wrong cable (store actions, the viewer gizmo's wrapper lookup, and the five Object-panel fibre editors). See [fiber.md](fiber.md) for the invariant and `store/__tests__/fiberNodesPerObject.test.ts` for the regression test.

- ~~**Half the left dock rendered as dead space.**~~ **Fixed 2026-08-24.** Docked panels split their zone with `flex: 1 1 0` plus a per-panel `flex-grow` weight, and the splitter between two of them hands out a *fractional* pair (0.45 / 0.55). Flex only fills the container when the weights **sum to ≥ 1**, so the moment the partner was collapsed or closed the survivor kept its 0.45 and 55% of the dock stayed blank — no panel, no background, nothing to grab. `FloatingPanel` now normalizes the weight against the expanded panels currently sharing the zone (`dockGrow`, `frontend/src/components/workspace/FloatingPanel.tsx:53`), which preserves the ratio the splitter set while always summing to 1. The stored `dockWeight` values are untouched, so an old localStorage layout heals on the next render.
